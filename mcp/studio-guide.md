# Как собирать письма в RetKit

## Дерево письма

Три уровня, порядок обязателен:

- **outer** — обёртка письма. Ровно одна, `parentUid: null`, `slotId: "root"`.
- **section** — секция. Лежит в обёртке: `slotId: "sections"`.
- **inner** — содержимое: заголовки, текст, кнопки, картинки. Лежит в секции: `slotId: "content"`.

Внутренний блок нельзя положить прямо в обёртку — только в секцию.
Порядок узлов в массиве задаёт порядок в письме.

Минимальное письмо:

```json
[
  { "uid": "o1", "blockId": "sys-outer",   "parentUid": null, "slotId": "root" },
  { "uid": "s1", "blockId": "sys-section", "parentUid": "o1", "slotId": "sections" },
  { "uid": "b1", "blockId": "sys-title",   "parentUid": "s1", "slotId": "content",
    "slots": { "text": "Заголовок письма" } },
  { "uid": "f1", "blockId": "sys-footer",  "parentUid": "o1", "slotId": "sections" }
]
```

## Наборы блоков

- **system** — короткий набор простых блоков (`sys-*`) для сервисных писем:
  подтверждения, документы, платежи, изменения условий.
- **promo** — весь каталог: комбо, герои, соцсети, кнопки магазинов.

Для сервисного письма всегда берите `kit: "system"` — там меньше кусков и ничего лишнего.

## Значения полей

Список полей блока даёт `retkit_get_block`. Не выдумывайте имена слотов.

- Пустая строка в цветовом поле значит «взять из темы бренда» — обычно это
  правильнее, чем вписывать HEX руками.
- У полей с `options` допустимы только перечисленные значения.
- Отступы между блоками ставятся сами: у секции есть `gap`, у обёртки — `gap`
  и `space_top`. Отбивки вручную добавлять не нужно.

## Готовый скелет одним блоком

`sys-starter` — комбо: логотип, заголовок, приветствие, два абзаца, подсвеченная
плашка, кнопка и футер. Часто быстрее взять его и удалить лишнее, чем собирать
письмо с нуля.

## Порядок работы

1. `retkit_list_blocks` — что вообще есть (для сервисного письма `kit: "system"`).
2. `retkit_get_block` — какие поля у выбранных блоков.
3. `retkit_compose_preview` — собрать и прочитать предупреждения.
4. `retkit_save_mail` — сохранить, когда предупреждений нет.

Не сохраняйте письмо, не собрав превью: сборка ловит несовместимые блоки и
неверные значения полей.

## Чего делать нельзя

- Придумывать блоки, которых нет в каталоге, — сборка их отвергнет.
- Класть внутренние блоки в обёртку, минуя секцию.
- Ставить плейсхолдеры локализации в готовый HTML: подстановка работает только
  при сборке из исходника, в HTML такой плейсхолдер останется текстом.

## Переводы письма — обязательный порядок

Перевод без плейсхолдеров **не применится**: сборка подставляет текст локали только
туда, где в исходнике стоит `${{ NS.block_NN }}$`. Делаешь переводы — ставишь и плейсхолдеры.
Плейсхолдеры живут в **Pug-исходнике**, не в HTML: ручной HTML поверх локали отвязывает её от Pug.

1. Письмо открыто во вкладке «Код» (из конструктора — `retkit_open_in_code`).
2. `retkit_email_texts` — тексты письма по порядку (вместо чтения всей вёрстки).
3. `retkit_set_locale_blocks` — локаль на языке письма (например `ru`) и эталон `en`,
   одинаковое число блоков в одном порядке. Namespace создастся сам.
4. `retkit_place_placeholders` (namespace) — ставит плейсхолдеры в Pug без модели,
   сам выбирает якорную локаль (ту, что совпала с исходником лучше всех), пересобирает.
5. `retkit_set_locale_blocks` — переводы (ar, es…): тот же порядок и число блоков,
   `{{…}}` и `@@…@@` не трогать.
6. `retkit_build_mail` с нужными локалями — посмотреть итог: тексты каждой локали и
   неподставленные `${{ }}$`. Не сдавай работу, не проверив этот шаг.

Для писем из базы RTL на `ar`/`ur` применяет сборка — отдельно ничего не нужно.
`translate_locale_txt` и `create_locale` с переводом требуют ключа модели студии —
свой агент переводит сам и пишет через `retkit_set_locale_blocks`.
