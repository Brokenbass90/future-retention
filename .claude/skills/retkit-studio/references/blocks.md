# Блоки: формат, наборы, слоты

## Файл блока

`data/block-library/<source>/<id>.json`:

```json
{
  "id": "sys-title",
  "label": "Заголовок",
  "description": "Крупный заголовок письма",
  "placement": "inner",
  "category": "text",
  "kits": ["system", "promo"],
  "pug": "…",
  "styl": "…",
  "slots": [
    { "id": "text", "kind": "text", "label": "Текст", "default": "Заголовок",
      "uiGroup": "content" },
    { "id": "align", "kind": "select", "label": "Выравнивание",
      "options": ["left", "center", "right"], "default": "left",
      "uiGroup": "appearance" }
  ],
  "slotPresets": { "size": { "large": { "font_size": "28", "line_height": "34" } } },
  "childSlots": []
}
```

## Размещение

- `outer` — обёртка письма. В письме ровно одна, `parentUid: null`, `slotId: "root"`.
- `section` — секция, лежит в обёртке (`slotId: "sections"`).
- `inner` — содержимое секции: заголовки, текст, кнопки, картинки (`slotId: "content"`).

Внутренний блок нельзя положить прямо в обёртку. Порядок в массиве = порядок в
письме.

## Наборы (kits)

- `system` — **белый список**: блок виден в наборе system, только если он явно
  объявил `"kits": ["system", …]`. Это короткий набор `sys-*` для сервисных
  писем: подтверждения, документы, платежи, изменения условий.
- `promo` — **fail-open**: блок без `kits` виден. Это весь каталог.

Логика в `blockAllowedInKit()` (`src/block-library-schema.js`) и её копии в
`public/constructor.js` — при правке менять обе.

## Слоты

`kind`: `text`, `richText`, `color`, `select`, `number`, `url`, `image`.
`uiGroup`: `content` (что написано) или `appearance` (как выглядит) — по нему
инспектор раскладывает поля на две группы.

**`slotPresets`** — выбор в одном слоте заполняет другие. Движок общий:
`slotPresetAssignments(block, slotId, value)`. Важно: инспектор обязан
применять пресеты через эту функцию, а не писать значение напрямую — один раз
на этом уже погорели, пресеты молча не срабатывали.

## Тема бренда

В `styl` доступны переменные `$brand_*`, которые подставляет
`brandThemeStylusHeader()`. Работают и функции Stylus (`mix()` и прочие).
Благодаря этому один блок перекрашивается под бренд, а не копируется под каждый.

Пустое значение слота цвета означает «взять из темы». Поэтому конструктор
подставляет фон обёртки из темы бренда явно: пустая строка до сборки не
доезжает, и письмо получало тёмный системный фон вместо светлого.

## Отступы

Отступы между объектами письма ставятся автоматически движком gap в
`src/compose-email.js` — это свойство раскладки, а не отдельный узел дерева.
Блок участвует, если объявил слот `gap` или `space_top`. После последнего
блока отступа нет.

## Превью

`npm run previews` — пререндер карточек каталога в `data/block-previews/`.
Блоки группируются в «контактные листы» и режутся по маркерам
`<!-- rk:block-start:UID:ID -->`, поэтому 1000 блоков стоят 50–100 сборок, а не
1000. Перерисовывается только то, у чего изменился хеш `pug+styl+slots+version`.

Известная беда (этап 8 роадмапа): превью рендерятся без подстановки
vendor-переменных, поэтому в футере видно буквальное
`{{embedded.company_address}}`, а кадр обрезается по фиксированному
прямоугольнику, а не по содержимому.
