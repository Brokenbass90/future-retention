# Как устроена студия внутри

## Путь запроса

Всё приходит в один обработчик `http.createServer` в `server.js`. Порядок
проверок важен и менять его нельзя:

1. `/healthz` — единственная ручка до авторизации.
2. Basic Auth (`isApplicationRequestAuthorized`), если включена.
3. **Актёр** — `resolveActor(__dirname, request)` кладёт в `request.retkitActor`
   метку того, кто пришёл, и ставит cookie, если метка новая.
4. Дальше — маршруты, длинной лестницей `if (method && url)`.

Ответы: `sendJson(response, status, payload)` и `sendText`. Ошибки двери к
письмам превращает в статус `mailStoreStatus(error)` — 409 для занятого письма,
403 для витрины, 404 для отсутствующего.

## Две поверхности

**Конструктор** (`public/constructor.js`, ~5400 строк) — дерево письма в
браузере. Узел = `{uid, blockId, parentUid, slotId, slots}`. Три уровня:
`outer` → `section` → `inner`. Холст хранится в `localStorage`, на сервер
уезжает только при сборке и сохранении.

**Воркбенч** (`public/workbench.js`, ~12600 строк) — код письма, локали,
предпросмотр. Открытое письмо живёт в `state.srcCtx = {brand, mail, files,
activeFile, …}`. При открытии берётся замок (`window.RetkitLease.hold`).

Общее у обеих поверхностей вынесено в отдельные файлы и подключается в оба
HTML: `actor-badge.js` (кто работает), `mail-lease.js` (занятость письма),
`mcp-connect.js` (подключение своего агента), `studio-chat.js` (чат).

## Сборка письма

Два разных пути, не путать:

**Из блоков** — `src/compose-email.js`: дерево узлов → `header.pug` +
`main.styl` в папке письма. Отступы между блоками ставятся автоматически
(движок gap внутри `renderItem`), тема бренда приезжает переменными
`$brand_*` через `brandThemeStylusHeader()`.

**Из исходников в HTML** — `email-base/tools/build-mail.js`, запускается
подпроцессом: `node tools/build-mail.js --category <BRAND> --mail <name>`.
Pug + Stylus + словарь локали → `email-base/dist/<BRAND>/mail-<name>/<LOCALE>/index.html`.

## Локализация

Источник — Pug. В нём стоят плейсхолдеры `${{ NS.block_01 }}$`, а значения
лежат в `email-base/vendor/data/<locale>/<NS>.json`. Сборка подставляет
значения нужной локали.

Ключевая механика (её просили и она работает): плейсхолдер ставится **один
раз в Original**, и при переключении локалей подтягивается перевод именно этой
локали. За перенос правки из скомпилированного HTML обратно в Pug отвечает
`src/original-text-sync.js` — и переносит только тогда, когда старый текст
встречается в Pug ровно один раз. Не уверен — не трогает.

Отдельный случай: `.retkit-workbench/html-overrides/<locale>.html`. Такой файл
**отвязывает** локаль от Pug навсегда — она перестаёт пересобираться. Создавать
его можно только по явной правке человека в этой локали.

## Разведение по людям

`src/actor.js` — кто работает. `human:<token>` (cookie), `agent:<token>`
(заголовок `x-retkit-token`, так приходит чужой Клод по MCP), `demo:<token>`
(витрина, только чтение). Карточки в `.retkit/actors/`.

`src/mail-store.js` — единственная дверь к файлам письма. Спрашивает
разрешение через заменяемый guard (`setMailWriteGuard`), поэтому замки
подключаются одной строкой в `server.js` и о них не знает ни одна ручка.

`src/mail-locks.js` — занятость. Явная лиза (90 с, heartbeat раз в 25 с из
вкладки) держит рабочую сессию. Молчаливая лиза на 8 с берётся самой записью и
разводит две одновременные записи, но нарочно не занимает письмо на будущее.
Протухание обязательно: запертое навсегда письмо хуже изредка перехваченного.

## Блоки и каталог

`data/block-library/canonical/` — блоки, написанные руками. `imported/` —
вытащенные из существующих писем. `user/` — созданные в студии.

Каталог собирается в память (`ensureBlockCatalog`), отдаётся по
`/api/blocks-library`. Карточка показывает пререндеренное PNG из
`data/block-previews/` — живой iframe на каждую карточку студия не тянет.

## MCP

`mcp/retkit-mcp-server.mjs` — stdio-сервер: чужой Клод подключается своим
клиентом и работает инструментами студии (каталог, блок, сборка, сохранение,
инструкция). Модель приносит пользователь; студия за неё не платит и ключей
не спрашивает.

`src/mcp-setup.js` готовит конфиг подключения, `public/mcp-connect.js` — мастер
в интерфейсе: три шага, автоустановка для локальной студии и копируемый конфиг
для удалённой.

## Что где хранится

| Путь | Что | В репозитории |
|---|---|---|
| `.retkit/actors/` | карточки актёров | нет |
| `.retkit/locks/` | занятость писем | нет |
| `.retkit-workbench/` | черновики HTML и отвязанные локали | нет |
| `email-base/dist/` | собранные письма | нет |
| `email-base/_trash/` | удалённые письма | нет |
| `data/block-library/` | блоки | да |
| `data/block-previews/` | превью блоков | да |
| `email-base/vendor/` | скелет и локали | да |
