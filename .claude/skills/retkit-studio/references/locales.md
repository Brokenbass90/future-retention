# Локали: как письмо становится переведённым

## Идея

Письмо пишется один раз. Тексты в нём заменяются плейсхолдерами, а сами тексты
лежат отдельно по локалям. Сборка подставляет словарь нужной локали и выдаёт
готовый HTML.

Ключевое требование, ради которого всё устроено именно так: **плейсхолдер
ставится один раз в Original**, а при переключении локалей на него
подтягивается текст именно этой локали. Расставлять плейсхолдеры руками в
каждой локали — это ошибка проектирования, а не «ещё один способ».

## Правило флоу: перевод ⇒ плейсхолдеры

Делаешь переводы — расставляешь плейсхолдеры. Порядок: эталонная локаль `en` →
плейсхолдеры по `en` → остальные локали тем же числом и порядком блоков.
Подробно — тема `emails`, раздел «Переводы письма».

## Где что лежит

```
email-base/<BRAND>/mail-<name>/app/templates/blocks/header.pug   ← источник
email-base/vendor/data/<locale>/<NAMESPACE>.json                 ← тексты
email-base/dist/<BRAND>/mail-<name>/<LOCALE>/index.html          ← результат
```

Формат плейсхолдера: `${{ NAMESPACE.block_01 }}$`. Есть ещё два вида, их не
путать:

| Вид | Что это | Кто подставляет |
|---|---|---|
| `${{ NS.block_01 }}$` | перевод | сборка, из `vendor/data/<locale>` |
| `{{embedded.x}}` | общая переменная письма (адрес, риск-ворнинг) | сборка, из vendor |
| `{% … %}` | служебная разметка стиля | не трогается |

Имя неймспейса нормализуется: `!TESTNAME` → `TESTNAME`, `bad namespace` →
`bad-namespace`. Ловится в `normalizeWorkbenchNamespaceName`.

## Перенос правки из Original в Pug

Человек правит текст в скомпилированном HTML оригинальной локали. Чтобы правка
не осталась запертой внутри локали, она переносится обратно в Pug —
`src/original-text-sync.js`, ручка `/api/wb/sync-original-text`.

Правило осторожности: перенос выполняется, только если старый текст встречается
в Pug **ровно один раз**. Иначе движок молча отказывается — лучше не перенести,
чем испортить письмо наугад.

Правка в НЕ оригинальной локали — это правка перевода, она идёт в JSON локали, а
не в Pug.

## Отвязанные локали

`.retkit-workbench/html-overrides/<locale>.html` — ручной HTML конкретной
локали. Такой файл **навсегда** отвязывает локаль от Pug: она перестаёт
пересобираться из источника.

Это мина. Один раз она уже сработала: автосохранение срабатывало на простое
открытие локали (потому что причёсанный HTML отличался от исходного пробелами),
локали тихо отвязывались, и «ничего не тянется». Поэтому:

- автосохранение обязано отличать реальную правку от косметической разницы
  (`htmlBufferHasRealEdits()` — сравнение с нормализацией пробелов между тегами);
- пустой буфер не сохраняется никогда (`htmlBufferIsSavable()`);
- отказ от черновика не должен запирать вкладку — `confirmDiscardHtmlDraft()`
  не возвращает `false`.

## RTL

Арабский и другие RTL-локали обрабатываются отдельным проходом сборки. Проверка
— `scripts/test-rtl.mjs`. Ломается обычно на inline-стилях с `text-align` и на
таблицах с фиксированной раскладкой.

## Проверки

```bash
node scripts/test-original-text-sync.mjs      # перенос правки в Pug
node scripts/test-build-mail-localization.mjs # подстановка словаря
node scripts/test-locale-cross-check.mjs      # локали не разъехались
node scripts/test-rtl.mjs
```
