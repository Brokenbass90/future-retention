## Что входит в текущую последнюю версию

- трёхуровневый конструктор `outer → section → inner`, раскрываемые combo и
  типизированные разделители;
- брендовые вкладки, темы, папки и отдельные семейства IQ Option/IQ Broker;
- крупный desktop/mobile preview блоков и детерминированный preview-каталог;
- HEX-цвета, поверхность блока, фон/рамка/радиус/отступы и исправленные
  email-safe CTA/asset layouts;
- Pug/Stylus-first Workbench, linked/detached HTML, атомарное сохранение
  исходников, CAS и per-mail lock;
- all-locale release preflight, immutable HTML snapshot и порог Gmail clipping;
- корректный CSS pipeline: обычные правила инлайнятся, необходимые media/
  client-specific rules остаются в `<head>`;
- безопасное разделение соседних `}} {{` только внутри CSS в `<head>` без
  изменения контентных плейсхолдеров;
- обновлённые IQ Broker blocks/combos и читаемые preview для светлого текста;
- необязательный локальный Ollama backend для text-first чата/draft/переводов;
  vision и constructor tool-agent пока OpenAI-only.

вне release commit.

## Следующий продуктовый цикл

### P0 — начать наполнять чистую базу

1. Выбрать одно реальное письмо IQ Option и одно IQ Broker.
2. Для каждого зафиксировать дизайн, локали, ссылки и системный footer.
3. Нарезать письмо на понятные атомы, секции и combo.
4. Прогнать desktop/mobile/RTL, Gmail/Outlook/Apple Mail и вес HTML.
5. Только прошедшие блоки переводить из candidate в approved/canonical.

### P1 — каталог как Finder

- единый browser с деревом `бренд → коллекция/кампания → письмо`;
- сохранённые фильтры, теги и избранное;
- такой же brand-aware browser для блоков;
- создание нового бренда с темой, папкой и стартовым набором токенов;
- универсальные блоки получают цвета темы, но сохраняют явный ручной override.

### P1 — визуальное качество

- обязательный visual regression для combo и крупных preview;
- отдельная RTL-матрица: направление колонок, выравнивание, цифры,
  punctuation, кнопки и mobile;
- Litmus/Email on Acid либо собственная матрица скриншотов Gmail, Outlook и
  Apple Mail перед релизом реальных кампаний.

### P2 — AI без потери ручного контроля

- картинка/Figma → proposal дерева существующих блоков;
- недостающий фрагмент создаётся как candidate, а не сразу canonical;
- visual diff и список изменённых Pug/Stylus/slots до принятия;
- генерация/редактирование картинок отдельным инструментом с asset provenance;
- Ollama можно использовать для классификации, draft и локальных текстовых
  задач, но approval, запись исходников и release остаются детерминированными.

### P2 — эксплуатация

- Postgres для писем/metadata и S3/R2 для assets/previews;
- изолированный build workspace или namespace lock для параллельных сборок;
- уменьшение preview churn и Heroku slug;
- постепенное разделение `server.js` на routes/services/build/storage.
