# Тест-план для Codex (и для себя) — актуально на build 2026-06-25h

Чтобы Codex прогонял проверки вместо ручного тестирования. Две части:
**А. автоматом** (логика, без браузера и ключа) и **Б. вручную в браузере**.

Перед началом: в DevTools-консоли при загрузке workbench должно быть
`[RetKit] build 2026-06-25h…` (или новее). Если версия старее — у тебя несвежий
бандл, и часть багов из списка будет видна, хотя в коде уже исправлена.

## А. Автоматические тесты (offline, без OpenAI-ключа)

> Запусти `npm test` и покажи итог по каждому файлу. Код не меняй.

`npm test` покрывает:
- `test-locale-align-tool` — выравнивание локалей под reference, `{{embedded.*}}` на месте (7).
- `test-locale-cross-check` — сверка локалей (9).
- `test-html-blocks` — вставка/удаление блока по якорю (11).
- `test-html-validate` — незакрытые теги / разбаланс `{{ }}` / `${{ }}$` / `@@` (8).
- `test-agent-loop`, `test-locale-crud-tools` — агентский цикл и CRUD локалей.

> `npm run test:blocks` — компиляция всех блоков библиотеки. Ожидается **25/25, 0 битых**.

> Сборка письма + doctype:
> `cd email-base && node tools/build-mail.js --category X_IQBroker --mail multiple-account-termination`
> → `[build] OK`; затем `grep -ao "<!DOCTYPE[^>]*>" dist/X_IQBroker/mail-multiple-account-termination/index.html`
> → должно быть `<!DOCTYPE html PUBLIC … XHTML 1.0 Strict …>`, НЕ `<!DOCTYPE public>`.

## Б. Ручная браузерная проверка (`npm start` + ключ для AI-частей)

Для каждого пункта: действие → ожидаемый результат. Отметить ✅/❌.

### Критические фиксы (проверить в первую очередь)
1. **Сохранить не ломает исходник.** Открой исходный файл письма (header.pug) → «Сохранить». Содержимое — код, НЕ `[object PointerEvent]`, не пусто. Пересборка проходит.
2. **Паддинг/стиль на крупном блоке не ломает письмо.** Карандаш → клик по большому `<td>` (карточка с картинкой+текстом+кнопкой) → поменяй ПАДДИНГ → Применить. Письмо НЕ разваливается; меняется только отступ контейнера, дети (картинка/заголовок/кнопка) на месте.
3. **doctype при компиляции** — `<!DOCTYPE html PUBLIC … Strict …>`, не `public`.

### Карандаш (инспектор превью)
4. Стиль на Pug-письме: цвет хексом `#ff0000` → Применить → Сохранить → цвет виден после пересборки; в pug строке появился `(style=…)`.
5. Глубина ⬆/⬇: клик по тексту → шапка `<p> 1/n` → `⬆` ведёт к `<td>`/`<table>` (счётчик растёт), выделение/подсветка переходят к родителю.
6. Box-model: паддинг ЗЕЛЁНЫЙ, маргин КРАСНЫЙ, бордер СИНИЙ на выбранном элементе.
7. Поля: «Высота строки», «Граница (border)», «Фоновая картинка (URL)» — для элемента с фоном URL ПОДХВАТЫВАЕТСЯ (не пусто); фон прозрачного элемента показывается «прозрачный», НЕ `#000000`.
8. Ссылка: выбери лого → `⬆` к `<a>` → поле «Ссылка (href)» показывает текущую ссылку и меняет её.
9. Карандаш на внешнем HTML-письме: правка текста/цвета применяется мгновенно, без ошибки «не найден фрагмент».

### RTL
10. Кнопка «⇄ RTL» в тулбаре превью на LTR-арабском письме → стороны зеркалятся (left→right), центр остаётся центром; повторное нажатие безопасно (идемпотентно).

### Локали через AI-агента (нужен ключ)
11. Без тумблера: «поправь в ru блок 2: …» → агент (timeline) → кнопка «↩ Применить локаль» → текст в ru меняется.
12. «сверь все локали с английской и приведи к единому виду» → align: число блоков выравнивается, `{{embedded.*}}` на местах.
13. Скриншот в чат (drag/paste) → «сделай как на скрине» → в start-фрейме «📷 N».
14. Агент: «проверь HTML на ошибки» → зовёт `validate_html`, находит незакрытые теги/разбаланс.

### Workbench UX
15. Разворот превью ⛶ → колонка кода скрывается, письмо на весь экран; ESC — назад.
16. Меню «⋯» — Outline, палитра блоков (Monaco убран).
17. Автозакрытие: печатаешь `<p>` → авто `</p>`; `(`/`"` закрываются парой.
18. Нижняя панель: растягиваешь вверх → почти весь экран; «База писем» заполняет всю высоту (нет пустоты снизу).
19. Экспорт TXT — папкой, без `footer_upload`.

### Конструктор `/constructor`
