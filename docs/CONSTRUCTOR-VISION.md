# DnD-конструктор писем — видение

Документ-видение (не код). Как сделать конструктор «полноценным и удобным».

## Что не так с текущей версией (`/constructor`)

Сейчас это 4 колонки: **Каталог | «Структура» (абстрактный список карточек) |
Превью | Инспектор**. Главная беда — письмо живёт в ДВУХ представлениях
одновременно: абстрактный `<ol>`-список, который ты редактируешь, и отдельное
превью, на которое только смотришь. Отсюда:

- тесно: 4 колонки на обычном экране = всё мелкое и неудобное;
- не WYSIWYG: руками работаешь по списку, а не по самому письму;
- инспектор оторван от элемента: выбрал карточку в списке → правишь слоты
  где-то справа, визуальной связи нет;
- drag = «добавить в конец списка», без понимания «куда блок влезает» на
  реальном письме;
- превью пересобирается кнопкой/дебаунсом, а не является рабочей поверхностью.

## Главный принцип

**Письмо — единственная рабочая поверхность. Канва И превью — это одно и то же.**
Рендеренное письмо и есть холст: на него перетаскивают блоки, по нему кликают
для правки. Никакого отдельного абстрактного списка.

Под капотом без изменений: источник истины = код блока (`{pug, styl, slots}`),
любая правка = правка слотов/структуры → пересборка через существующий
`build-mail.js` / `/api/compose-preview`. Визуал никогда не расходится с кодом.

Три глубины на одном фундаменте:
1. новичок — собирает мышкой из блоков;
2. «немного шарит» — правит текст/цвет/скругление кликом по элементу;
3. верстальщик — открывает Pug/Stylus во вкладке workbench.

## Раскладка (макс. широко и удобно)

Две колонки + центр, обе боковые сворачиваются в иконку — тогда письмо
занимает почти весь экран:

```
┌──────────┬───────────────────────────────┬───────────┐
│ ПАЛИТРА   │      ЖИВОЕ ПИСЬМО (холст)      │ ИНСПЕКТОР  │
│ блоков    │   — рендер, drop, клик-правка  │ контекст-  │
│ (сворач.) │   — между секциями: зоны для   │ ный        │
│ section/  │     section-блоков             │ (или пла-  │
│ inline/   │   — внутри секций: зоны для     │ вающий у   │
│ my blocks │     inline-блоков              │ элемента)  │
└──────────┴───────────────────────────────┴───────────┘
   верх: имя письма · устройство desktop/mobile · ▶ собрать · 💾 сохранить
```

- Палитра слева: вкладки **Outer (секции)** / **Inner (элементы)** / **Мои блоки**,
  поиск, крупные превью-тумбы. «➕ Создать блок» остаётся.
- Инспектор справа — **контекстный**: пуст, пока ничего не выбрано; по клику на
  элемент показывает правки именно для него. В идеале — плавающая панель у самого
  элемента (как pencil-mode), чтобы связь «правлю вот это» была очевидна.
- Обе боковые сворачиваются → режим «чистый холст».

## Взаимодействие

### Перетаскивание (drag)
- Тянешь **section**-блок (hero, фичи, CTA, футер) → подсвечиваются зоны вставки
  МЕЖДУ секциями письма.
- Тянешь **inline**-блок (кнопка, картинка, абзац, иконка) → подсвечиваются зоны
  ВНУТРИ секций (контентные слоты), а межсекционные гаснут.
- Несовместимое сочетание (section на inline-слот) → дроп запрещён, тултип
  «секционный блок сюда не влезает».
- Технически: при сборке в превью каждый блок помечается маркерами
  `rk:block-start/end` (это уже реализовано в `compose-email.js` через `markBlocks`),
  по ним фронт сопоставляет DOM-диапазон ↔ блок и рисует линию вставки реальным
  DOM-узлом внутри iframe (без пиксельной математики).

### Клик-правка на месте (карандаш встроен в холст)
Клик по элементу в письме → инспектор/плашка с правками по типу элемента:
- текст → редактируемое поле + B / I / ссылка;
- картинка → замена URL / загрузка;
- кнопка/контейнер → фон, цвет текста, скругление, padding, ширина.
Каждое изменение пишется в слот блока (Pug/Stylus) и письмо пересобирается.
Это самый ценный слой — правка существующих писем без всякого drag.

### Перетаскивание для порядка и удаления
- Секции письма можно тащить вверх/вниз (reorder), удалять крестиком,
  дублировать. Серверный фундамент уже есть: `insert_block` / `remove_block`
  (по якорю) + маркеры секций.

### Личная библиотека
Правый клик по выделению в письме → «Сохранить как блок»: имя, категория,
placement (определяется автоматически), слоты угадываются из `{{ token }}` →
сохраняется в `data/block-library/user/` и появляется в палитре «Мои блоки».

## Инспектор по типам элементов (что показывать)

| Элемент | Контролы |
|---|---|
| Текст / заголовок | textarea, B/I, ссылка, размер, цвет, выравнивание |
| Картинка | URL / загрузка, ширина, alt, ссылка-обёртка |
| Кнопка (CTA) | текст, href, фон, цвет текста, скругление, padding, ширина |
| Контейнер/секция | фон, padding, выравнивание, фоновая картинка |
| Любой блок | его слоты из `slots[]` (kind: text/richText/url/color/image/number/select) |

## Связка с AI (уже частично готово)

- `compose_email_from_blocks` — агент собирает письмо из блоков по описанию;
  каждый блок предтестирован → результат гарантированно компилируется.
- `insert_block` / `remove_block` — добавить/убрать блок в открытом письме
  (фундамент drag-вставки и удаления).
- «Скинь скрин макета» (vision) → агент предлагает последовательность блоков →
  ты докидываешь недостающие картинки → сборка.
- `align_locales_to_reference` — при добавлении/удалении блоков тексты локалей
  остаются по местам.

## Совместимость с почтой (важно после кейса RTL-в-админке)
- Все блоки — Outlook-safe таблицы, без `float` для раскладки (float выкидывают
  строгие клиенты — это и ломало футер). Двухколоночные элементы — только таблицей.
- Превью желательно дать переключатель «строгий клиент» (рендер без float и т.п.),
  чтобы такие баги ловились в конструкторе, а не в админке.

## Порядок постройки (предложение)

1. **Слить «Структуру» и «Превью» в один холст** — рендеренное письмо становится
   единственной поверхностью (убрать абстрактный `<ol>`). Это превращает 4 тесные
   колонки в удобные 2+центр.
2. **Клик-правка (pencil) на холсте** — инспектор по типам элементов. Самый
   высокий по отдаче слой, работает и без drag.
3. **Drag section-блоков** на холст со смарт-зонами между секциями.
4. **Drag inline-блоков** внутрь секций + reorder/удаление/дублирование секций.
5. **Личная библиотека** (save as block).
6. **Вернуть вход из workbench** (кнопку), когда конструктор уже удобный.
7. **AI-сборка из блоков и из скрина** поверх готового холста.

Кнопку входа из workbench возвращаем на шаге 6 — когда есть что открывать.

## Дополнение (сессия 2)

### Письма из pug-базы vs внешние
- **pug-база** — родной случай: блоки вставляются/удаляются/переставляются на уровне
  Pug-исходника, есть маркеры, чистая пересборка. Полная мощь.
- **внешние письма** (произвольный скомпилированный HTML, без Pug):
  - лёгкие операции работают уже сейчас — `insert_block`/`remove_block` и карандаш
    оперируют по уникальному якорю в HTML-строке, без Pug;
  - полное блочное редактирование — через **ИИ-ингест с апрувом**: ИИ режет внешний
    HTML на узнаваемые блоки (hero/CTA/футер), показывает карту, пользователь
    ПОДТВЕРЖДАЕТ, после чего HTML размечается маркерами блоков (reorder/удаление)
    либо пересобирается из канонических блоков (design-to-blocks). Апрув обязателен —
    авторазбор произвольного HTML не идеален.

### Откат (undo) для drag-and-drop
Фундамент уже есть: стек снимков на 20 шагов (`_undoSnapshots` /
`pushUndoSnapshot` / `restoreUndoSnapshot`). Нужно: (1) звать `pushUndoSnapshot`
на каждой DnD-операции (вставка/удаление/перестановка), (2) постоянная кнопка ↶
над превью, шагающая назад по стеку (несколько ходов).

### Реализовано в этой сессии (UX)
- **Навигация по глубине в инспекторе** — клик по элементу собирает цепочку предков;
  в шапке инспектора ⬆ (наружу к родителю) / ⬇ (внутрь) + метка `<tag> i/n`. Решает
  проблему перекрытия/вложенности блоков.
- **Разворот письма на весь экран** — кнопка ⛶ в тулбаре превью прячет колонку кода
  (`.workspace.preview-maximized`), ESC сворачивает.
- **Drag-drop картинки в чат** — файл-референс падает в чат и уходит агенту (vision).
- **Фикс «карандаш → сохранить ломается»** — `stripPreviewArtifacts()` чистит
  preview-обёртки/скрипты, инспектор правит чистый исходник, сохранение не пишет мусор.
