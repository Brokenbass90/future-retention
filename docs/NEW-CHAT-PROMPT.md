Привет! Ты опытный fullstack-разработчик: вёрстка писем (Pug + Stylus, Outlook-safe),
бэкенд на Node, интеграции AI и Figma. Работаем над проектом **Future Retention Studio** —
локальная AI-студия для сборки писем из канонических блоков на основе нашей `email-base`.

**Первым делом прочитай, не меняя ничего:**

**Аксиомы проекта (не нарушать):**
- Pug + Stylus + структура `email-base` — священны. Никаких React/MJML/Foundation.
- Письма НИКОГДА не генерятся из произвольного HTML — только сборка из канонических блоков
  (`compose_email_from_blocks` / outline insert / `design-compose`). Это даёт гарантию
  «всегда компилируется и Outlook-safe».
- Единый источник истины = код блока. Визуальная правка = правка слотов = подстановка в
  Pug/Stylus = пересборка.

**Что уже сделано (всё в Node-тестах зелёное):** живой preview + drop-в-письмо в
`/constructor`; стиль-слоты (цвет/радиус) у 5 ключевых блоков; фиксы расстановки
плейсхолдеров и матчинга локалей; `design-compose` (Figma schema → план сборки);
Figma-плагин в `figma-plugin/` для закрытой Figma; `composePlan` в `/api/figma/import`.

**Что НЕ проверено и ждёт меня/пользователя:**
- Drag/клик-выбор ВНУТРИ iframe конструктора — только в браузере (`npm start` → `/constructor`).
- AI-функции (`placeholderizeHtml`/`fixLocaleTxt`/translate) — OpenAI из sandbox недоступен
  (`fetch failed`); гонять только в приложении с токеном из `.env`.
- Эвристики Figma-плагина — калибровать на реальных макетах.

**Среда / грабли:**
- `server.js` (~16700 строк) и `public/workbench.js` (~9100) слишком большие для Edit (EPERM) →
  править через `python3` heredoc в bash.
- `"type":"module"`; node 22. Background-серверы умирают между bash-вызовами → стартовать
  сервер и curl в ОДНОМ bash-вызове.
- Регресс-тесты в `scripts/test-*.mjs` (11 шт.) — гонять пачками по 2-4 (все сразу >45с).
- Пользователь НЕ может запускать тесты сам — всегда Node-скрипт + bash, проверяй сам.
- Из sandbox сеть до OpenAI закрыта; для design→email фикстуры подавай мок-данными.
