# PROJECT RULES — доменные конвенции студии

Единый источник правды о соглашениях ретеншн-команды. Эти правила:
- кодифицированы в `src/locale-conventions.js` (детерминированный normalizer);
- подмешаны в системные промпты AI (агент, fix-locale, translate);
- проверяются валидатором локалей в workbench;
- покрыты тестами `scripts/test-locale-conventions.mjs` и `scripts/test-placeholderize-units.mjs`.

Меняешь правило — меняй все четыре места.

---

## 1. Виды токенов

| Токен | Что это | Где живёт |
|---|---|---|
| `${{ ns.block_NN }}$` | Плейсхолдер ТЕКСТА студии (с долларами) | только в HTML письма |
| `{{embedded.company_email}}`, `{{user_name}}`, `{{Level_Name}}` | СКВОЗНАЯ переменная платформы (без долларов) | в HTML — литералом; в TXT — отдельным токеном |
| `{{обычный текст}}` | Переводимый блок локали | только в TXT |
| `@@текст@@` | Маркер жирности внутри блока | в TXT; зеркалит `<b>/<strong>` в HTML |

**Эвристика переменной:** содержимое `{{ }}` — идентификатор без пробелов,
содержащий точку или подчёркивание (`/^[A-Za-z][A-Za-z0-9-]*(?:[._][A-Za-z0-9._-]*)+$/`).
`{{Hello}}` — текст. `{{user_name}}` — переменная.

## 2. Переменные НЕ живут внутри текстовых блоков

Неправильно:
```
{{If we can help, contact your manager or {{embedded.company_email}}.}}
```
Правильно (блок разбит вокруг переменной, точка — отдельным блоком):
```
{{If we can help, contact your manager or}} {{embedded.company_email}}{{.}}
```
- Нумерация `block_NN` сквозная по ВСЕМ токенам файла (переменные тоже получают номер).
- В HTML такой абзац выглядит так:
  `${{ ns.block_06 }}$ {{embedded.company_email}}${{ ns.block_08 }}$`
  — переменная остаётся литералом, её подставляет платформа рассылки (другая админка).
- Переменные не переводятся. Во всех локалях токен одинаковый.
- Placeholderize анкерит «текст + переменная + хвост» как ОДИН юнит
  (см. `buildAnchorUnits`), сам блок-переменная никогда не анкерится как текст.

## 3. Subject-строка

`Subject: ...` в начале TXT — служебная строка для админки. Живёт ВНЕ блоков,
не оборачивается, не считается ошибкой «текст вне блоков», в вёрстку не попадает.

## 4. Жирность

`@@фраза@@` в блоке локали зеркалит жирность фразы в вёрстке. При починке локалей
AI может сам добавлять `@@`, глядя на HTML (`<b>/<strong>`), и обязан сохранять
существующие маркеры парными при переводе.

## 5. Как студия применяет правила

- **Кнопка «Авточинить»** в редакторе локали: шаг 1 — конвенции (POST
  `/api/wb/locale-normalize`, zero-AI), шаг 2 — выравнивание структуры по reference.
- **Агент**: инструмент `normalize_locale_conventions` (zero-AI, локаль или 'all').
  Промпт требует вызывать его ДО placeholderize/fix при найденных вложенных переменных.
- **Валидатор** (`parseTxtDetailed`): вложенная переменная в блоке → ошибка
  `nested_variable` с подсказкой про Авточинить; Subject вне блоков → не ошибка.
- **Перевод/починка AI**: промпты знают конвенции (переменные verbatim, Subject verbatim).
