## Что было не так (диагноз по коду)

В workbench три пути чата:
1. **🤖 выключен + «расставь плейсхолдеры»** → клиентский zero-AI шорткат
   `maybeApplyPlaceholdersFromLocales` (workbench.js). Это НЕ AI — regex+DOM. Он
   вставляет в HTML токены `${{ ns.block_NN }}$` («странный код в поле кода») и
   осознанно НЕ трогает локали («Загруженные локали не изменены»). Это и был симптом.
2. **🤖 выключен + обычный текст** → discussion-чат: только читает/анализирует.
3. **🤖 включён** → настоящий агент с полным CRUD локалей и правкой HTML.

Вывод: способность менять видимые локали уже была, но пряталась за тумблером 🤖.

## Что сделано

### Fix 1 — авто-маршрутизация в агента (убрана ловушка тумблера)
`public/workbench.js`: `looksLikeEditIntent()` + новая логика в `sendAiMessage`.
Запросы-правки (поменяй/исправь/переведи/создай локаль/вставь блок/жирным/лого…)
теперь сами идут в настоящего агента, если live AI доступен (`state.aiConfigured`
из `/api/status`). Тумблер 🤖 = «всегда агент». Zero-AI шорткат остаётся фолбэком,
когда ключа нет (offline). Чистые вопросы по-прежнему идут в обычный чат.

### Fix 2 — скриншоты в агента (vision)
`workbench.js` теперь кладёт прикреплённые картинки в тело `/api/wb/ai/agent`.
`server.js` пробрасывает `images` в `runAgent`. `src/ai-agent.js` добавляет их как
`input_image` в сообщение пользователя; системный промпт знает про скриншоты.
До 4 картинок. Теперь «скинул скрин → агент видит макет и понимает, что делать».

### Fix 3 — сверка всех локалей между собой
`src/locale-cross-check.js` (новый) + инструмент `compare_locales` в `src/ai-tools.js`.
Zero-AI, offline. Ловит: разное число блоков, пропущенные/лишние `{{vars}}`,
рассинхрон `@@bold@@`, нечётные `@@`, пустые (непереведённые) блоки, блоки дословно
равные reference (забытый перевод). Триггеры: «сверь/сравни все локали».
Тест: `scripts/test-locale-cross-check.mjs` (9/9).

### Fix 5 — выравнивание всех локалей под reference (привести к единому виду)
`align_locales_to_reference` в `src/ai-tools.js` (детерминированно, zero-AI, через
`src/locale-conventions.js`). Сравнивает все локали с английской и ПРИВОДИТ к
идентичной структуре: одинаковое число блоков, тот же порядок, платформенные
`{{embedded.*}}` на тех же позициях; нехватка блоков добивается пустыми спейсерами;
конвенции (вложенные переменные, баланс скобок) нормализуются, reference тоже.
Это шаг, после которого `placeholderize` встаёт по местам. Триггеры: «сверь с
английской и приведи к единому виду», «выровняй блоки по en». В отличие от
`compare_locales` (только отчёт) — это ДЕЙСТВИЕ, возвращает localeUpdates по каждой
изменённой локали. Системный промпт: при дрейфе локалей сначала align, потом
placeholderize. Тест: `scripts/test-locale-align-tool.mjs` (7/7).

### Fix 4 — добавить/убрать блок в открытом письме
`src/html-blocks.js` (новый) + инструменты `list_email_sections`, `insert_block`,
`remove_block`. Безопасно по уникальному якорю (как `replace_in_html`), без нарезки
вложенных таблиц — поэтому письмо не ломается. `insert_block`: anchor +
before/after или body_start/body_end. `remove_block`: уникальный блок или from..to;
отказ при удалении >50% документа. Маркеры `rk:block` (письма из конструктора)
распознаются отдельно. Тест: `scripts/test-html-blocks.mjs` (11/11).
Это фундамент будущего DnD (reorder/remove). DnD-UI — позже, как и договаривались.

## Как проверить в приложении (нужен ключ)

1. `npm start`, открыть workbench, открыть письмо + загрузить локали (вкладки сверху).
2. БЕЗ нажатия 🤖 написать: «поправь в ru второй блок: …» → должен запуститься агент
   (timeline с tool-calls), появиться кнопка «↩ Применить локаль ns/ru», и текст
   во вкладке ru реально измениться после клика.
3. «сверь все локали» → агент зовёт `compare_locales`, в сводке — расхождения по локалям.
4. «создай локаль de с переводом из en» → `create_locale` → кнопка применения новой вкладки.
5. Прикрепить скриншот макета + «сделай как на скрине» → в start-фрейме видно «📷 N»,
   агент ссылается на содержимое картинки.
6. «убери блок с …» / «добавь под hero такой блок …» → `remove_block` / `insert_block`,
   кнопка «↩ Применить HTML», изменение в preview.
